# Deployment and recovery checklist

## Understand the snapshot

Treat these files as reviewed deployment references, not a one-command installer. The private edition contains installation-specific IDs and absolute paths; the public edition contains example values and documentation-only addresses. A new installation must regenerate IDs, network settings, local service paths, trust and credentials. Do not overwrite a running installation with a Git checkout.

## Dependencies

- Linux gateway with Python 3.12, Docker Compose, systemd user services, OpenSSH client and GitHub CLI (`gh`).
- GPU inference endpoints configured for amd-gpu and nvidia-gpu; models named in `deployments/hermes/team.py` must be available.
- Hermes pinned image and source revision in `deployments/hermes/release.json`.
- Paperclip pinned image in its Compose file; upstream revision `d554c4789ed3930f8a53ac9fdf6503b3187097da` records the inspected source snapshot.
- Python YAML support for YAML-reading helpers/tests. File parsing dependencies are provided by the pinned Hermes image.
- Paperclip UI plugin build dependencies are supplied by the Paperclip SDK/build environment; inspect `control-center/build.cjs` before rebuilding.

## Provision in this order

1. Choose the deployment root and edit absolute systemd/Compose/script paths to match. Configure host addresses and TLS trust, keeping inference, research collection and operator credentials separated.
2. Restore required secrets through local enrollment or a private secret store. Create `.env` from the adjacent examples, supply trusted TLS material and API credentials, and verify private file permissions. Never commit those generated files.
3. Prepare n8n/PostgreSQL and Paperclip using their component READMEs. For a fresh Paperclip installation, bootstrap the administrator locally and run the setup helpers to generate new company/project/agent IDs; copied historical IDs do not create resources.
4. In Hermes, inspect and run `prepare.py`, then the Paperclip/Suits/diagnostic setup helpers appropriate to the installed services. `prepare.py` creates local credentials and profiles but is not a substitute for configuring endpoint credentials/trust.
5. Enroll Discord with the intended private server/channel and allowed users. Configure Message Content Intent and channel permissions; never grant Administrator just to fix channel access. Keep account-mention-only behavior.
6. Install the fixed local diagnostic probe on each approved host. Configure host trust and the selected observer/password transport locally. Network research must remain on HQ.
7. Install and enable the supplied systemd services/timers after editing their paths. GitHub requires `gh auth login` on HQ and the private `github-origin` key generated by preparation. Create `run/github` and `state/github` before starting its protected service. Check the owner enrollment and repository allowlist.
8. Build/install the Paperclip Control Center plugin from source if required. Register the Suits agents and verify actual assignments in the UI.
9. Run `python3 hq.py doctor`, applicable offline tests, and explicit live acceptance checks. Confirm Discord owner/friend mention rules, owner-only GitHub, inference receipts, task follow-ups, and no secret exposure.

## Restore boundaries

Source control does not restore Paperclip/n8n databases, Discord conversations, files, credentials or GitHub proposal history. Restore those from the private backup system separately. Review pending task-notification and GitHub proposal state before enabling senders on a replacement gateway, and run only one active gateway per restored state set.

See [recovery](deployments/hermes/docs/recovery.md), [backups](deployments/hermes/docs/backups.md), and [GitHub operation](deployments/hermes/docs/github.md). The backup helpers are not a license to interrupt production services without the operator's selected approval.

For public deployments, copy `deployments/hermes/config/publication-private-terms.json.example` to the ignored `.json` path and configure your private names locally. Do not publish the real blocklist into the public repository.

For the research browser, provision Docker build access to the pinned Playwright image and npm package, then run `python3 prepare.py` and `docker compose up -d --build renderer render-fetch broker` from deployments/hermes. The browser has no host port or external network route; the public-fetch relay is separate. Keep the supplied seccomp profile and Chromium sandbox enabled. Run `python3 validation/check_research_browser.py` after deployment. This is source for the configured installation, not a promise of unattended fresh-host enrollment.

## Current integration prerequisites

Read [individual Google setup](deployments/hermes/docs/workspace.md) before enabling Gmail/Calendar; each user needs their own OAuth enrollment. Do not reuse another user's credentials. The exported configuration uses placeholders and cannot authorize Google on its own.

Read [Herdr integration guidance](deployments/hermes/docs/herdr.md) for an operator terminal setup. The source snapshot does not install Herdr. Discord long replies require Attach Files permission in each destination; Paperclip links retain the application's normal authentication requirements.

## Context and telemetry services

Mount the new context_settings.py, gpu_telemetry.py and read-only context configuration through the generated Hermes Compose file. Keep the configuration directory mount, so atomic CLI changes are visible without stale single-file mounts. Preserve per-request broker context settings and profile metadata together.

Install/enable systemd/hq-hermes-stack.service and its timer for the company dashboard snapshot. This is separate from evidence refresh. Upgrade the fixed AMD diagnostic probe for exact VRAM/power metrics and PCI identity. Rebuild/reload Control Center 0.1.3 using its existing plugin upgrade path. The dashboard does not need a new external telemetry service. See the context and dashboard runbooks for application, rollback, privacy boundaries and validation.

## Vault and Benjamin prerequisites

Provision OpenBao with verified release artifacts, local TLS, encrypted storage and an explicit recovery-key plan before starting containers that bind `/run/hq-vault-runtime`. Read `deployments/vault/README.md` and the secure enrollment runbook. The archived `initialize.py` is installation-specific migration code whose former plaintext inputs were removed; do not blindly rerun it. The provided install script is a first-install reference, not a complete upgrade/recovery orchestrator.

Install the root-owned vault Python modules and operator CLI. Retain all systemd units, including **hq-vault-connector.socket** and its matching service; socket activation is required. Configure the local Unix account/group in those files. Create the four named service credentials through private enrollment and provision narrowly scoped AppRoles, then create/hydrate runtime credentials before starting the broker/worker. Bootstrap credentials and recovery keys must be generated locally and never committed. Unattended unlock trusts the host administrator; choose a stronger key service or manual unlock if your requirements differ.

Register Benjamin through `setup_team_paperclip.py --execution-only` only after the existing worker and team IDs exist. Mount server_ops.py and its separate access token as shown in Compose. A new vault entry is not usable by an agent until a connector for that service is implemented. Benjamin's server connector exposes fixed read-only operations.

## Per-agent Hub migration

`deployments/hermes/setup_hub.py` migrates an existing configured installation by same-filesystem rename and compatibility links. Stop active agent writers and take a private checkpoint before applying it. Review its source/destination mapping and adapt the user/home path. The source installation must already exist; this is not a fresh-host bootstrap command. Retain original compatibility paths while existing tools reference them.

Install the root-owned `hub_sandbox.py` service and `hq-hub-sandbox.socket`/`.service`; configure the local account and pinned Python image. Only fixed per-agent workspace mounts are allowed, with no network or credentials. Mount hub_store.py, the existing document extractor and agent folders as generated by prepare.py. Configure the owner-authenticated hq_hub tool and per-agent worker mounts. Install the optional daily `hq-hub-backup` user timer for private work-file snapshots. It does not replace application database or vault backup.
