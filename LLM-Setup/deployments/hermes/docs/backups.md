# 6. Backups and validation

## What exists

| Source | Location | Scope |
|---|---|---|
| Paperclip full local backup | `../paperclip/backups/TIMESTAMP/` | Database dump plus instance/configuration/credential archive |
| Paperclip autogenerated SQL | `../paperclip/data/instances/default/data/backups/` | Application-generated compressed database SQL |
| n8n full local backup | `../n8n/backups/TIMESTAMP/` | Quiesced database dump, n8n data and deployment/secrets |
| Hermes local backup | `backups/TIMESTAMP.tar.gz` | Deployment code/configuration, profiles, private state and credentials |

These local archives contain credentials and are not encrypted off-host copies. Private permissions are essential. Do not upload or attach them to chats or tasks. No archive-deletion policy is enabled.

Paperclip's database dump is transactionally consistent, but its live configuration/file archive is not a globally atomic snapshot across the database and all files. n8n's helper pauses its application services for a coordinated capture. A full recovery drill is still needed for both applications.

## Create backups

Run these from the Hermes directory only during an authorized maintenance window where interruption applies:

```bash
python3 ../paperclip/backup.py
sudo python3 ../n8n/backup.py
python3 backup.py
```

The n8n helper stops only previously running n8n/proxy/runner services and resumes exactly that set in its failure handler. PostgreSQL remains running. Hermes backup briefly stops only this deployment's running services, then resumes them. Do not run backup commands during active agent work.

## Verify the actual dump

```bash
python3 verify_database_backup.py paperclip
sudo python3 verify_database_backup.py n8n
sudo systemctl start hq-backup-observations.service
systemctl --user start hq-hermes-evidence.service
```

The verifier uses the production PostgreSQL image ID but creates a unique temporary container with no network, no production volume mounts and disposable storage. It restores tables, reads accompanying archives for integrity and removes the temporary container. A private `restore-validation.json` is written beside the dump. The metadata exporter accepts the proof only if its SHA-256 matches the current dump.

Passed checks prove database restore and archive readability, not restored logins, credential decryption, workflow correctness or whole-VM boot recovery. Hermes backup validates extraction, credential byte roundtrip and SQLite integrity but does not start a second gateway.

## Scheduling

`hq-backup-observations.timer` and the daily Paperclip backup-review routine **monitor backups; they do not create them**.

`backup_maintenance.py` and `systemd/hq-backup-maintenance.*` are prepared for daily 03:30 America/New_York. Activation remains pending approval for recurring n8n interruption. The job would create Paperclip/n8n full backups, test restores and refresh metadata. It refuses to start below 10 GiB free and deletes no archives. A missed maintenance run does not run automatically at boot.

After approval, enable on HQ with:

```bash
install -m 644 systemd/hq-backup-maintenance.service systemd/hq-backup-maintenance.timer ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now hq-backup-maintenance.timer
systemctl --user list-timers hq-backup-maintenance.timer
```

Review free space and establish retention before accumulated backups become a capacity problem.

## Off-host backup decisions

Still required: destination host/share/path, transport and account, encryption recipient, separate offline recovery-key custody, retention, and a restore test. Existing encrypted n8n tooling is described in `../../docs/credential-security.md` relative to the deployment directory; it is not evidence that off-host copies are running. Never store the only recovery key alongside the encrypted backup.
