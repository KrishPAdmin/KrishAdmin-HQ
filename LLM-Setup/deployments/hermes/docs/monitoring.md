# 4. Monitoring and history

## Commands

```bash
python3 hq.py alerts
python3 hq.py history --limit 20
python3 hq.py report
python3 hq.py doctor
```

In Discord, ask the bot to show active warnings and recent changes. The native `hq_status` tool supports `view: alerts`; this returns the same deterministic assessment used by the CLI.

## Default rules

Rules are maintained in `health_rules.py`; changes should be reviewed and tested before restarting the broker.

| Condition | Finding |
|---|---|
| Inference API unavailable | Critical |
| A loaded model reports zero GPU residency | Critical |
| No model currently loaded | Not an outage by itself |
| Root disk at least 80% / 90% used | Warning / critical |
| Available RAM below 10% / 5% | Warning / critical; one sample is not proof of a sustained shortage |
| Host snapshot older than 600 seconds, future dated, or unavailable | Warning; stale resource measurements are not used for resource alerts |
| Missing host telemetry | Warning; separate from API reachability |
| Backup metadata older than 600 seconds, future dated, or unavailable | Warning |
| Latest backup older than 36 hours | Warning |
| Backup absent/unreadable | Warning |
| Explicit database-restore failure | Critical |

Off-host storage not configured and full application recovery not tested are **setup gaps**, not current outages. Untested does not mean failed. A database-only autogenerated Paperclip backup is not covered by a different full backup's validation receipt.

## History behavior

`monitor.py` polls without invoking a model and writes `state/monitor.json` atomically with private permissions. It retains up to 288 samples (roughly 24 hours at five-minute intervals) and 200 alert transitions. It records new alerts, severity changes and recovery. Unchanged alerts are not repeated as new events. If collection fails, existing alerts are retained; failure to collect is not evidence of recovery. Historical recovery events must not be presented as current outages.

Current live status is authoritative for the current reading. The history includes its own timestamp and freshness indicator. Retention is a count limit; manual runs can shorten the elapsed time represented. No Discord/email notifications, automatic repair, task creation or archive deletion occurs in the monitor.

## Interpreting a clean result

`no_active_observation_alerts` means no configured rule fired for the available measurements. It is not a complete hardware-health certification. Use the coverage fields and setup gaps alongside it.
